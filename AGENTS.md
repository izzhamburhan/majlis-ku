# Majlis Ku: Agent Guide (Codex, Gemini CLI, Copilot, others)

Claude Code reads `CLAUDE.md`; both files describe the same project and rules. Keep them in sync.

## What this is

A mobile-first web platform for Malaysian events with two products: a **QR digital guestbook** (guests scan one QR code and, with no app and no account, upload photos, videos, voice messages and wishes into a live gallery and venue slideshow) and an **e-invitation card with RSVP** (template, details, map, countdown, WhatsApp-friendly share link). The full brief is `docs/brief.md`. Bahasa Melayu is the default language, English the second. Currency MYR, timezone `Asia/Kuala_Lumpur`.

## Process

`playbook.md` is the process: gates 0 to 7, git and branch rules, validation commands, Definition of Ready and Done, review checklist. Short version: classify, discover, set up a worktree, write the spec, write the TDD plan (the developer approves both), confirm the baseline, implement test-first, verify with fresh output, let the developer choose commit, push, or PR, then hand off. Do not commit or push without the developer's say-so.

The product is built in the eight phases listed in `docs/brief.md`, one spec (`docs/specs/phase-<n>-<slug>.md`) and one plan (`docs/plans/phase-<n>-<slug>.md`) per phase. After a phase: run the app, run the tests, summarise, and wait for the developer's "continue".

Worktrees: `sh scripts/worktree-add.sh <branch>` creates `.worktrees/<branch>` so agents can work in parallel; `sh scripts/worktree-cleanup.sh` removes merged ones.

## Agent roles

The session you start is the orchestrator: it runs the gates, asks the developer, decides, and holds commit and push approval. Scouting, single-slice implementation, and reviews go to the role agents in `.codex/agents/` (source in `.claude/agents/`, regenerated by `node scripts/skills.mjs sync`): `majlis_scout` (read-only discovery), `majlis_implementer` (one TDD slice in its own worktree), `majlis_reviewer` (per-slice review), `majlis_final_reviewer` (spec review, whole-branch review, payments, auth, deletion). Full rules: `playbook.md` §12.

## Current priorities

Decided by the developer on 2026-10-20: get the whole system working locally first. No hosting decision and no payment gateway yet. Plans and limits are still enforced, and an admin can set an event's plan by hand; the real `PaymentProvider` (phase 6) waits until the developer asks for it. Local development needs only Node.js: the database runs through `embedded-postgres` and media is stored on the local disk behind the same storage interface that S3 or R2 will use later.

## Stack

Next.js (App Router), TypeScript strict, Tailwind CSS, PWA. PostgreSQL with Prisma 6 (locally through `embedded-postgres`). Auth.js v5 for hosts: email magic link (printed to the server log in development) and Google. A `StorageDriver` interface: `local` disk with app-signed upload and download URLs now, S3-compatible (R2 or S3) presigned uploads later. `sharp` thumbnails. `ffmpeg-static` for video and voice copies in an in-process job queue. Server-Sent Events for realtime from an in-process bus. Payments deferred; later a Malaysian gateway behind a `PaymentProvider` interface. Zod at every boundary. Vitest and Playwright. Local first; Docker and hosting later. Do not change the stack or add a paid service without the developer's approval.

## Layout

`src/app/` App Router routes (guest, host dashboard, admin, api). `src/server/<domain>/` server-only domain logic (events, uploads, wishes, rsvp, plans, media, auth, admin, reports, retention, security, ...). Routes live under `src/app/[locale]/` (`[slug]` guest, `i/[slug]` card, `dashboard`, `admin`) and `src/app/api/`. `src/lib/` zod schemas, money in sen, dates, i18n. `src/components/` UI. `messages/` `ms.json` (default) and `en.json`. `prisma/` schema, migrations, seed. `tests/unit/` Vitest, `tests/e2e/` Playwright. `docs/brief.md` the product brief; `docs/specs/` and `docs/plans/` per phase. `playbook.md` the process. `.codex/skills/` process and guard skills (source in `.claude/skills/`). `.codex/agents/` role agents (source in `.claude/agents/`). `scripts/` worktree, skill and agent sync, and local Postgres (`db.mjs`). `.github/` CI and PR template. `.mcp.json` MCP servers (Playwright, Prisma). Full tree in `docs/specs/phase-1-setup.md`.

## Commands

First run: `npm install`, `cp .env.example .env` (fill `AUTH_SECRET` with `npx auth secret` and `HASH_SALT` with any long random string).

```bash
npm run db:start             # local PostgreSQL on the DATABASE_URL port (5433 by default); keep it running
npx prisma migrate dev
npx prisma db seed           # safe to run twice
npm run dev                  # http://localhost:3000 ; demo guest page /demo-aisyah-daniel
npm run lint
npm run typecheck
npm test
npm run build                # prints first-load JS per route
npm run test:e2e             # needs a fresh `npm run build`
node scripts/skills.mjs sync
node scripts/skills.mjs check
```

Local sign-in: with `EMAIL_SERVER` empty the magic link is printed in the server log and appended to `.data/dev-mail.log`; emails in `ADMIN_EMAILS` become admins, checked on every request (removing an email revokes access); admins are read-only on host dashboards and act through `/admin`. If port 5433 is taken, change the port in `DATABASE_URL` in `.env`. To test on a phone, set `NEXT_PUBLIC_APP_URL` and `AUTH_URL` to `http://<LAN-IP>:3000` and run `npm run dev -- -H 0.0.0.0`. Read `NEXT_PUBLIC_APP_URL` through `env()` in server code, never `process.env.NEXT_PUBLIC_*` (frozen at build time). Do not run `next dev` and `next build` together (shared `.next/`), and stop old `next start` processes before e2e (one started without `CRON_SECRET` makes the cron e2e fail with 404). `GET /api/health` returns 200 `{ "status": "ok" }` when the database answers, 503 otherwise.

## Rules

1. Server owns the truth: prices, plan limits, quotas, and moderation state come from the database. Never trust a price, size, kind, or count sent by the client.
2. Validate every boundary with Zod: route handlers, server actions, webhooks, env variables, form input.
3. Domain logic lives in `src/server/<domain>/` as plain, unit-tested functions; route handlers and server actions only parse, authorize, call, and respond.
4. Guests have no account: a display name plus a device token cookie, scoped to one event. Never require a guest login, email, or phone number to upload.
5. Private by default: galleries private unless the host opts in, media through short-lived signed URLs, optional event PIN.
6. Uploads go straight to object storage through presigned URLs, issued only after plan, size, and type checks, and confirmed (magic bytes, size) before they become visible.
7. Money is integer sen, currency `MYR`. No floats for money.
8. Payments go through `PaymentProvider`. Webhooks verify the signature, are idempotent, and are the only thing that marks a payment paid.
9. Store time in UTC, show it in `Asia/Kuala_Lumpur`.
10. Bahasa Melayu is the default locale; every user-facing string lives in `messages/ms.json` and `messages/en.json`.
11. Guest pages stay under 150 KB of JS on first load and work on low-end Android, slow 4G, and in-app browsers.
12. Tests first, TypeScript strict, no unexplained `any`.
13. PDPA: consent text on the upload screen, host can delete an event and all its media, no raw IPs stored, no real personal data in seed or tests. Purge: when an event's retention ends (`Event.purgeAt`: plan retention counted from the event date, or from creation, the last date change or a plan change if later) it is archived: files and guest records (uploads, wishes, RSVPs, guests, abuse reports, e-card) are deleted and the event row is kept as `ARCHIVED`, read-only. It runs hourly inside the server (`src/server/retention/`) and on `POST /api/cron/purge` with `Authorization: Bearer <CRON_SECRET>` (404 when unset). A host edit moves `purgeAt` only when the event date changes. Rate limits live in the `RateLimit` table, shared by every server. `src/lib/legal.ts` holds placeholders (`[NAMA SYARIKAT]`, `[EMEL]`, `[ALAMAT]`) shown on `/privacy` and `/terms`; fill them and have a lawyer review both pages before launch.
14. Never commit `.env`. `.env.example` documents every variable.
15. MCP servers in `.mcp.json`: `playwright` (browser checks, screenshots, e2e debugging) and `prisma` (migrations and local database). Add one only with the developer's approval and record it in both handbooks.
